# Read Daily 0.3.1

Read Daily 0.3.1 是切报性能与并发一致性修复版本。它保留 0.3.0 的固定八报、原版/OCR、中文摘要和 Obsidian 发布边界，不包含任何报纸正文或版面数据。

## 下载文件

- `Read-Daily-v0.3.1-macOS-arm64.zip`
- `Read-Daily-v0.3.1-macOS-arm64.zip.sha256`

## 运行条件

- Apple Silicon Mac
- macOS 13 或更高版本
- Python 3
- 只有在线抓取中国建设报并生成 PDF 时需要 Chrome 或 Chromium

当前包采用 ad-hoc 签名，未使用 Apple Developer ID 公证。解压后首次启动，请在 Finder 中右键 `Read Daily.app`，选择“打开”；不要关闭系统级安全保护。

## 本版修复

- 点击另一份报纸后立即切换选中态并显示独立加载进度，不再等待阅读动作与整日仪表盘串行完成
- 连续快速点击时取消旧请求，只有最后一次选择能够更新正文；旧响应不会闪回先前报纸
- 整期详情使用容量为 8 的 LRU 内存缓存，返回已经读取的报纸无需再次启动后端；保存草稿或生成预览后会失效对应缓存，避免旧告警残留
- 阅读状态改为后台写回；自动 opened、手动 completed、刷新和外部更新并发时，以最新已确认状态为准
- 收件箱、Banner 与报纸行的已读数字使用同一显示状态，加载期间右侧明确显示“正在读取整期报纸”
- 客户端工作台命令绕过一层 Python 转发；后端延迟导入仅导入所需模块，概览接口不再无条件构造完整文章或哈希全部证据
- 有草稿、已发布建设报或完整期次请求时仍执行强证据摘要，性能优化不降低发布与篡改检测边界
- 大型 OCR 整期载荷在后台完成结构映射，不再占用界面主线程；跨设备迟到的旧阅读响应不会覆盖较新状态
- 归档读写固定在同一目录句柄，跨进程锁能够识别同一目录的大小写路径别名，避免并发阅读记录丢失
- 导入的原始 PDF 现在会用固定目录句柄重新计算 SHA-256 并与入库摘要核对；未篡改的既有草稿与发布记录保持兼容

## 性能验证

在 2026-09-02 的本地八报真实归档上，使用同一系统 Python、相同参数，分别预热一次后按交错顺序运行 24 次：

| 路径 | 0.3.0 平均 | 0.3.1 平均 | 改善 |
|---|---:|---:|---:|
| 首次读取中国建设报整期 | 173.090 ms | 68.233 ms | 60.6%（2.54×） |
| 读取当日仪表盘 | 347.262 ms | 118.789 ms | 65.8%（2.92×） |

以上是本机进程级基准，不代表所有设备的绝对耗时；重复返回已缓存报纸时不会再次调用整期 API。
