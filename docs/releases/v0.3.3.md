# Read Daily 0.3.3

Read Daily 0.3.3 修复“八报任务结束但只有 3 份成功”的根因，并把失败结果、精确原因与定向补抓能力封装进 Mac 客户端。它延续固定八报、原版/OCR、中文摘要和 Obsidian 发布边界，发布包不包含任何报纸正文或版面数据。

## 下载文件

- `Read-Daily-v0.3.3-macOS-arm64.zip`
- `Read-Daily-v0.3.3-macOS-arm64.zip.sha256`

## 运行条件

- Apple Silicon Mac
- macOS 13 或更高版本
- Python 3
- 只有在线抓取中国建设报并生成 PDF 时需要 Chrome 或 Chromium

当前包采用 ad-hoc 签名，未使用 Apple Developer ID 公证。解压后首次启动，请在 Finder 中右键 `Read Daily.app`，选择“打开”；不要关闭系统级安全保护。

## 本版修复

- 人民日报：从首版同目录导航发现并验证完整 20 版，复用首版响应，并以紧邻下一版的 404/410 确认期末；忽略桌面页中的平板阅读器链接，不把并行站点误判成重复版次，也不把连续前缀误归档为整期
- 光明日报：正文只取权威 `m-article-main` 容器，避免父子容器重复拼接
- 经济日报：兼容无引号 `id=ozoom` 与标题容器，正文仍必须有明确闭合边界
- 南方日报：支持 `A01`、`CC01` 等真实混合版码，保留原版码并以发现顺序建立稳定内部编号
- 北京日报：仅当标题明确为“图片新闻”、正文非空且页面存在普通或自闭合图片证据时接纳短图注；普通空正文或过短正文继续整期拒绝
- 中国建设报：PDF 不再用 100 KiB 作为完成信号，改为验证 PDF 头、最终 EOF 和与版数一致的实际页数；有效小文件可在稳定后立即进入归档，渲染进程仍运行时不会把短暂停写误判为最终失败
- 客户端：显示具体失败原因和正在抓取的报纸；部分成功使用黄色结果提示，并提供“仅补抓失败/缺失报纸”，不会重抓已成功来源
- 补抓完成后刷新当日状态，同时保留用户当前报纸、当前版次和抓取期间产生的未保存编辑

## 真实结果与性能

以下是 2026-09-03 在同一台 Mac、同一网络环境下，以全新空归档执行完整八报抓取的单次端到端结果。计时包含公开站点网络请求、版面下载、正文解析、校验和原子归档。

| 场景 | 成功结果 | 总耗时 |
|---|---:|---:|
| 修复前基线 | 3/8 | 227.59 秒 |
| 0.3.3 | 8/8 | 128.10 秒 |

本次实测同时把成功率从 37.5% 提升到 100%，总墙钟时间降低约 43.7%。随后只针对用户真实归档中原失败的 5 家报纸执行补抓，5/5 在 93.76 秒内成功；用户 2026-09-03 当日仪表盘最终为 8/8。
