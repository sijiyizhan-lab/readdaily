# Read Daily 0.3.2

Read Daily 0.3.2 进一步降低切换报纸和批量抓取的等待时间。它延续 0.3.1 的固定八报、原版/OCR、中文摘要和 Obsidian 发布边界，不包含任何报纸正文或版面数据。

## 下载文件

- `Read-Daily-v0.3.2-macOS-arm64.zip`
- `Read-Daily-v0.3.2-macOS-arm64.zip.sha256`

## 运行条件

- Apple Silicon Mac
- macOS 13 或更高版本
- Python 3
- 只有在线抓取中国建设报并生成 PDF 时需要 Chrome 或 Chromium

当前包采用 ad-hoc 签名，未使用 Apple Developer ID 公证。解压后首次启动，请在 Finder 中右键 `Read Daily.app`，选择“打开”；不要关闭系统级安全保护。

## 本版改进

- 八报抓取默认使用 4 个 worker 跨报纸并行执行，可通过 `--workers 1-8` 调整；同一报纸内部仍按 fetch → parse 顺序串行完成，避免版面与正文交叉写入
- 抓取状态与普通读报状态分离：后台抓取使用独立任务和进度文案，不再把整日抓取误显示为当前报纸详情加载，抓取期间仍可切换和阅读已有报纸
- 普通详情读取使用报纸目录及证据文件的元数据修订标识，不再在每次切报时读取并哈希全部版面图或 PDF；保存草稿、生成发布计划和正式发布仍执行完整内容摘要校验
- 旧草稿首次通过完整摘要兼容校验后会持久补齐当前元数据修订标识，后续读取直接走快速路径；草稿正文、校对内容和原保存时间保持不变
- 报纸来源与日期采用细粒度跨进程锁，不同报纸可以并行；遇到归档身份、事务或内存级严重错误时，会取消尚未开始的任务，并等待运行中的原子事务安全退出
- 版面图采用有界解码缓存，并按文件修订与目标尺寸区分缓存项；相同图片的并发解码请求会合并，主图高清解码期间先显示同版低清缩略图，减少重复解码和空白闪烁
- 同日跨报纸、抓取中换版、抓取失败复位、迟到输入法回调及拖放临时文件均加入真实异步回归；抓取期间原版缩放与摘要编辑保持可用，保存、发布、设置和导入仍受互斥保护

## 性能验证

以下结果来自同一台本地 Mac。每个版本和场景先预热 2 次，再执行 24 次配对交错测量；版本先后顺序各占一半。区间为 10,000 次 bootstrap 得到的 95% 置信区间。

|  | 0.3.2 | 67.16 ms（65.76–68.76） | 66.30 ms（64.96–67.67） | 75.70 ms（68.15–77.55） |

### 八报合成抓取

合成场景包含 8 个独立来源，每个来源固定模拟 100 ms 网络型 I/O。0.3.1 按来源串行运行，0.3.2 使用默认 4 worker；两者均包含批次锁和各自的调度开销，所有写入位于临时目录。

| 模式 | 平均耗时（95% CI） | 中位数（95% CI） | P95（95% CI） |
|---|---:|---:|---:|
| 0.3.1 串行 | 831.37 ms（829.91–832.84） | 831.22 ms（828.97–831.95） | 837.48 ms（834.55–838.60） |
| 0.3.2，4 worker | 224.33 ms（222.30–226.46） | 223.44 ms（221.99–226.65） | 232.91 ms（228.44–234.76） |

默认 4 worker 将平均耗时降低 73.0%；配对中位加速 3.73×（95% CI：3.66×–3.76×），实测最大并发数由 1 提升到 4。

### 基准限制

- 真实详情读取为 OS 页缓存预热后的稳态结果，没有清空系统文件缓存；它不包含 SwiftUI 布局、版面图解码或屏幕绘制时间
- 选取的中国建设报和人民日报当日没有持久草稿，因此没有计入旧草稿首次完整校验与修订标识迁移的一次性成本
- 合成抓取仅模拟可并行的网络等待，不代表真实报纸站点限流、连接质量、OCR 计算、各来源时延差异或并发峰值内存
- 每组只有 24 个正式样本，P95 尤其容易受单次系统调度波动影响；绝对耗时会随设备、归档规模和运行环境变化
