# 架构说明

## 总览
```
sources.json(注册表) ── fetch.py ──▶ per-adapter ──▶ <archive>/<source>/<date>/issue.json
                                             │                │
          ┌──────────────────────────────────┘                └─ _state/...（fetched→parsed→summarized→archived→tracked）
          ▼
  reader.py（prepare→LLM→ingest→archive→digest→tracking）──▶ Obsidian vault
          ▲
  readdaily query / status / tracking（CLI 会话接口）
```

## 适配器接口（新渠道只需实现 2 个函数）
```python
def fetch(src, d, archive_root) -> (issue_dict, err|None)   # 版次+版面图+文章链接/全文
def parse(src, d, archive_root) -> (issue_dict, err|None)   # 全文/OCR 文本注入 units
```
- `wechat_read`：搜狗精确标题定位 → src=11 签名直链 → 电子报版面图 → Vision OCR 版级文本（macOS）
- `founder`：方正/amucsite；index_url 版次发现 + `window.layoutData`（版图/文章/正文）+ 裸 div 兜底
- `paper_api`：JSON-API 型（uv/article/* 匿名接口 + articleId 全文）
- `cms_index`：index.json 携带当日最新期 → 显式文件路径（绕 WAF 目录封禁）

## 状态机与幂等
`_state/<source>/<date>.json` 记录各阶段时间戳；已完成的阶段自动跳过；失败阶段记录值可断点重跑。
期号连续性校验（chain_check）：上一期±1；方正系期号提取在 roadmap（可先以版数/文本量为替代校验）。

## LLM 通道（归纳层）
仓库定义为"通道可插拔"：
- 模式 A：Agent/用户会话代跑（README 路线，零 API 成本）——LLM 按 `_summaries` schema 产出
- 模式 B：`--llm-api`（OpenAI 兼容端点 + 环境变量 API KEY）→ 定时无人值守（roadmap，接口已预留）
schema：summary(100-150字)/category[政治|经济|军事|民生|生产|科技|文化|生态|其他]/entities[]/importance(1-5)/keywords[]

## 安全与合规
- 数据根放 `~/Library/Application Support/readdaily`（macOS TCC 保护 Download/Documents，launchd 写这两处会被拒——实测踩坑修复）
- 只抓公开内容；不绕过验证码/登录；订阅源（环球时报）需用户授权或放弃

## LLM 通道（模式 B 已实现 0.2.0）
`skills/newspaper-reader/scripts/llm_pipeline.py`：OpenAI 兼容 API 逐篇归纳（JSON schema+校验+重试）→ 注入 issue.json → 归档 → LLM 每日摘要 → top 实体自动跟踪。配置 llm.json（chmod 600/不入库）或 READDAILY_LLM_* 环境变量；vault 可经 settings.json/READDAILY_VAULT 指向用户自己的 Obsidian。
